<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Visitor → hosted client shell | An unauthenticated visitor can enter arbitrary resume, contact, credential, secret, and job-search content into a shared writable demo. |
| Client → existing API/storage | Existing browser actions continue writing through the unchanged API to JSON files; this phase does not create isolation or access control. |
| Server → optional AI provider | When an optional provider is selected, resume and job-posting content crosses to the configured third-party service; heuristic mode stays local. |
| Developer → runtime configuration | Provider keys and server environment settings are loaded from the server/.env file in local development and Render environment variables in production. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-16-01 | Information disclosure | Hosted App-shell warning and README | high | mitigate | Place explicit always-visible no-private-data guidance in App.jsx and README.md; test the required terms so route navigation cannot bypass the notice. |
| T-16-02 | Information disclosure | AI provider configuration | high | mitigate | Document the exact content transfer boundary in AI_PROVIDERS.md and distinguish it from local heuristic processing before users enable a provider. |
| T-16-03 | Tampering | Shared hosted JSON behavior | medium | mitigate | State that the demo is shared, writable, disposable, and resettable; do not imply account isolation or durable storage. |
| T-16-04 | Misconfiguration | README runtime/environment instructions | medium | mitigate | Derive versions from root/client/server manifests and document server/.env based on the root dev:server command; verify documentation gates without changing deployment config. |
| T-16-SC | Tampering | Dependency installation | high | mitigate | Add no packages; verify package manifests and lockfiles are unchanged by the phase and run the existing lint/test/build gates. |
</threat_model>
