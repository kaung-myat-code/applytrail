<objective>
Make add-type patches honor target_entry: attach the bullet to the named experience/project entry when it matches, and fall back to the last entry with a visible skip reason when it does not.

Purpose: The WR-06 limitation (bullets always land on whatever entry happens to be last) is a correctness bug for tailored resumes. This plan fixes the patch engine server-side (schema-independent — it reads suggestion.target_entry as data) and exports the sanctioned resume matcher so the OUT-04 eval reuses it.

Output: applyPatches.js gains SKIP_REASON.TARGET_ENTRY_NOT_FOUND and targetEntry-aware applyAddToList; applyPatches.test.js gains five target_entry cases; validate.js exports findInResume/normalizeText and warns on unmatched target_entry; validate.test.js gains a warning case.
