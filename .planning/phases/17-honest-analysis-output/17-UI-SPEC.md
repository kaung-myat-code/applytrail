# Phase 17 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope Note

Phase 17 is primarily a backend/behavior change (heuristic fabrication removal, AI prompt
guardrails, score normalization fix, `target_entry` patch targeting, eval harness). The
frontend surface area is deliberately small and surgical:

| Requirement | Frontend work? | Surface |
|-------------|---------------|---------|
| OUT-01 (remove fabrication templates) | None — heuristic produces fewer/zero suggestions; existing ReviewSuggestions empty state already handles this honestly | — |
| OUT-02 (honest gap notes) | Yes — new honest copy rendered in the existing "Gaps to Address" block on Analysis | `client/src/pages/Analysis.jsx` `ScoreDisplay` |
| OUT-03 (AI prompt guardrails) | None — server-side prompt change only | — |
| OUT-04 (eval set + script) | None — Node script + fixtures, no UI | — |
| OUT-05 (`target_entry` patch targeting) | Yes — new `SKIP_REASON` enum value mirrored client-side; distinct skip copy in PreviewTailored | `client/src/lib/skipReasons.js`, `client/src/pages/PreviewTailored.jsx` |
| OUT-06 (AI score 0–100 fix) | None — the frontend already renders `{score}` with a `/100` label correctly; the bug is purely server-side (`ai.js` rescale block) | — |

No new pages, routes, or components are added. This contract governs copy and a
single new skip-reason classification inside two existing components, plus confirms
the existing design tokens are sufficient (no new tokens required).

being introduced. The entire shipped client (v1.0–v2.1, deployed to Render) is built on plain
CSS Modules with hand-authored CSS custom-property tokens in `client/src/index.css`. Introducing
shadcn mid-milestone, for a surgical honesty pass on an already-shipped app, would be a
disruptive out-of-scope architectural change — this follows the shadcn gate's "N" branch:
`Tool: none`, registry safety gate not applicable. The token system below is pre-existing and
this phase adds no new tokens.

## Color

Pre-existing tokens from `index.css` — no new color tokens are added by this phase. The
decision below is a judgment call, documented for the planner/checker: gap notes reuse the
existing danger/red dot treatment already used by "Gaps to Address" rather than introducing a
new "informational" semantic color, since this is a surgical phase and re-painting an existing
block's color is out of scope.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#faf9f7` (`--color-bg`) / `#ffffff` (`--color-surface`) | Page background + card surfaces |
| Secondary (30%) | `#e8e5f0` (`--color-border`), `#8a839b` (`--color-muted`) | Card borders, secondary/label text |
| Accent (10%) | `#5b4cdb` (`--color-primary`) | Primary CTAs ("Analyze Match", "Generate Tailored Resume"), links, focus rings |
| Destructive | `#c74040` (`--color-danger`) | Defect skips, validation errors — **not** used for gap notes |
| Semantic (existing, reused) | `#2d9d78` success / `#c07d2b` warning / `#c74040` danger | Keyword badges, score circle, skip-warning banners — unchanged |

**Accent reserved for:** primary CTAs (Analyze Match, Generate Tailored Resume, Save to
Library), nav links, focus rings (`--shadow-focus`), "Back to Analysis"/"Back to Suggestions"
links. Never for gap notes, skip warnings, or keyword badges.

**Gap-note color decision:** The existing "Gaps to Address" block (`.gaps li::before`) already
uses a `--color-danger` red dot. OUT-02's honest gap note ("not on your resume; add a bullet
only if you have real experience") is informational-honest, not a defect — but changing this
block's color is out of scope for a surgical phase and risks over-designing an existing,
already-shipped surface. **Decision: keep the existing red-dot treatment, change only the copy
string the server emits.** If a future milestone wants to re-tone this as neutral/informational,
that is a separate, explicit design pass — not assumed here.

**Target-entry-not-found skip color:** Reuses the existing `.skippedWarning` amber/warning
banner styling in `PreviewTailored` (not `.skippedErrors` red) — this is a "heads up, verify
where this landed" state, not an internal-error/defect state. Matches the existing
`isDefectSkip`/non-defect classification: non-defect skips already render in the amber
`.skippedWarning` block, and `target-entry-not-found` buckets with them (per research
assumption A3).

## Copywriting Contract

No CTA changes this phase — PATH-01's "Analyze match" CTA rework is explicitly Phase 18, not
Phase 17. The primary CTA stays exactly as-is.

| Element | Copy |
|---------|------|
| Primary CTA | "Analyze Match" — unchanged (Phase 17 does not touch CTA hierarchy) |
| Empty state heading (Analysis, no resumes) | "No resume versions found." — unchanged |
| Empty state body (Analysis, no resumes) | "Create a resume to run match analysis." — unchanged |
| Empty state heading (Analysis, no postings) | "No job postings found." — unchanged |
| Empty state body (Analysis, no postings) | "Add a job posting first to run match analysis." — unchanged |
| Empty state (ReviewSuggestions, zero suggestions) | "Your resume already covers the key requirements well. No suggestions at this time." — unchanged; triggers more often post-OUT-01 as honest low-suggestion output becomes normal |
| Error state (analysis failed) | Existing generic error block — unchanged |
| Destructive confirmation | None — Phase 17 introduces no destructive actions |

**NEW copy — OUT-02 gap notes (rendered in Analysis "Gaps to Address" block):**

Per missing keyword, server emits one line in this exact format (mirrors OUT-02 requirement
text verbatim):

```
{Keyword}: not on your resume; add a bullet only if you have real experience.
```

Example rendered line: `Docker: not on your resume; add a bullet only if you have real experience.`

This replaces (is additive to) the current vague aggregate gap strings like
`"3 posting keywords missing from resume"` — the heuristic should emit one honest line per
missing keyword alongside (not instead of) the existing per-section match-rate summary strings
(e.g. `"Experience: only 45% keyword match"`), since those serve a different purpose
(section-level vs keyword-level honesty).

**NEW copy — OUT-05 `target-entry-not-found` skip reason (`PreviewTailored.jsx`):**

The existing `staleSkips` block currently renders one generic string for all known non-defect
skips: *"the resume content it targeted no longer matches exactly."* This does NOT fit
`target-entry-not-found`, which means something different (the suggestion named a specific
company/project to attach to, but that name doesn't match any live entry, so the bullet landed
on the last entry instead — it was not skipped entirely, it was mis-targeted with a visible
reason).

`PreviewTailored.jsx` must branch copy on `s.reason` within the `staleSkips` group:

- `NOT_FOUND` / `CURRENT_MISMATCH` — keep existing string: *"the resume content it targeted no
  longer matches exactly."*
- `TARGET_ENTRY_NOT_FOUND` — new string: *"no entry named "{target_entry}" was found — this was
  attached to your most recent {section} entry instead."* (e.g. *"no entry named "Acme Corp" was
  found — this was attached to your most recent experience entry instead."*)

Both render inside the existing amber `.skippedWarning` block — no new color/component needed,
just per-reason string selection instead of one shared string.

**Optional / not required this phase (flagged, not contract):** Surfacing `target_entry` on the
`SuggestionCard` (ReviewSuggestions page) *before* the user accepts an add-type AI suggestion —
e.g. a small "will attach to: Acme Corp" line. OUT-05's literal requirement covers the patch
engine behavior and the visible skip reason on *fallback*, not a pre-acceptance preview. This is
scope creep for a surgical phase — flagging as a nice-to-have only, not part of this contract.
If the planner wants it, it needs its own explicit decision, not an assumed default.
