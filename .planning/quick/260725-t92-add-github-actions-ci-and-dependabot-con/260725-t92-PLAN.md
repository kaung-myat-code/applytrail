  <name>Task 1: Create GitHub Actions CI workflow</name>
  <files>.github/workflows/ci.yml</files>
  <action>
Create the CI workflow. Name it "CI". Trigger on `push` to branch `main` and on `pull_request`
(all branches — no branch filter). Define one job `verify` running on `ubuntu-latest` with a
matrix strategy over `node-version: [18.x, 20.x]`.

Job steps in order:
1. `actions/checkout@v4`.
2. `actions/setup-node@v4` with `node-version: ${{ matrix.node-version }}`, `cache: npm`, and
   `cache-dependency-path` listing all three lock files as a multiline block:
   `package-lock.json`, `client/package-lock.json`, `server/package-lock.json`. This is required
   because npm caching in a monorepo must hash every lock file, not just the root one.
3. Install dependencies with `npm ci` at repo root (no `working-directory`). The root `postinstall`
   script installs client and server deps automatically, so a single root `npm ci` covers all three
   packages. Do NOT add separate install steps for client/server.
4. Lint: `npm run lint` (root script delegates to client eslint only — server has no lint script, so
   do not attempt to lint the server).
5. Test: `npm test` (root script chains client vitest then server node tests).
6. Build: `npm run build` (root script builds the client via vite).

Give each step a clear `name`. Do NOT add any deploy steps, secrets, environment variables, Render
hooks, or caching beyond setup-node's npm cache. This is CI verification only.

Use `${{ matrix.node-version }}` interpolation for the node version. Keep YAML 2-space indented.
  </action>
  <verify>

  </verify>
